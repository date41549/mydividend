# 成長戦略・実装ロードマップ：マイ配当

> 2026-07-30 に方針決定。以降このドキュメントが「今後どの順で作るか」の正。
> マネタイズの詳細設計は [04_monetization.md](04_monetization.md)、集客は [07_go_to_market.md](07_go_to_market.md)、競合は [01_competitive_analysis.md](01_competitive_analysis.md)。

## 決定サマリー（2026-07-30）

- **位置づけ＝B：収益プロダクトとして育てる**（ブランド/ポートフォリオ資産に留めるA案は不採用）。
- **マネタイズ＝サブスク一本**。深掘り分析・CSV取込・自動取得・バックアップ等を月額課金で解除。
- **広告＝当面入れない（将来オプション）**。理由は下記「広告を入れない根拠」。MAUが十分伸びて広告収益が無視できないと分かった段階でのみ、最小1バナーを再検討する。
- **前提の直視**：市場は飽和・課金意欲は狭い。中位でも月 数千〜数万円規模。だからこそ「課金する強い理由（競合の無料が持たない価値）」を最短で積む設計にする。

## 設計思想（順序を決める原則）

1. **既に無料で出した機能は据え置き**（ツリーマップ FR-13／ヒストグラム FR-14／税引後 FR-16／通知 FR-17）。後から有料化＝既存ユーザーの反感・レビュー低下。無料の強さは ASO とレビューの武器。
2. **「売る価値」→「課金土台」→「モート」の順**。売るものが無いのに課金土台だけ作らない／課金導線が無いのにモートだけ厚くしない。
3. **外部依存なし→あり**。自己完結の機能を先に、外部APIやデータ源に依存する重い機能を後に。
4. **Dev Build 移行は課金を解禁する一回きりの関門**。ここを越えると RevenueCat（課金）も将来の広告も可能になる。OTA（expo-updates）は移行後も維持され、JSのみ修正は引き続き `eas update` で配信できる。

## 広告を入れない根拠（サブスク一本の理由）

- **収益が薄い**：トラッカーは起動頻度が低く、弱気 約2,000円/月・中位でも約2万円/月。中位が出る規模なら課金も効くので、広告はそこで足を引っ張る。
- **差別化を自分で折る**：売りは「モダン・広告控えめ・軽量」＝首位（配当管理・63万DL）の最頻出不満「広告が多い」を突く戦略。自分も広告を出すと後発無名の同型に落ちる。
- **プライバシーの物語を壊す**：両ストアに「データ収集なし・トラッキングなし・端末内だけ」で申告済み。広告（特にパーソナライズ）は収集/トラッキングありへの申告変更＋iOS の ATT ダイアログを招き、「証券連携しない安心」という売りと矛盾する。
- **課金の圧が抜ける**：ニッチ本気層は「機能の壁」で払う。広告という不快を挟むと「我慢すればいい」になり課金圧のガス抜きになる。
- **非対称なリスク**：無名のうちに広告付きで出すと「また広告アプリか」の刷り込みが最初に付く＝武器が育つ前に死ぬ。クリーンで出しておけば将来足す判断はいつでもできる（逆は難しい）。

## 実装ロードマップ（この順で作る）

| Ver | テーマ | 中身 | 狙い |
|-----|--------|------|------|
| **v1.0.x** | 土台を閉じる | ① Android 本番公開（クローズドテスト→製品版）② 溜めた FB（FB3 ステッパー／FB2b 新形式コード）を OTA 配信 ③ **ASO 一次最適化**（タイトル/サブ/キーワード/スクショ）④ アプリ内レビュー依頼導線（`expo-store-review` 等） | 無料の入口品質を最大化。流入と定着の器を先に整える |
| **v1.1** | 課金の"看板"を用意 | **FR-15 増配追跡**：配当履歴データモデルを追加 → 連続増配年数・配当推移・増減配。高配当ガチ勢が唯一無二で欲しがる分析。外部依存なしで作れる | 「売る価値」を先に用意する |
| **v1.2** | 課金をオンにする | **EAS Dev Build 移行 → RevenueCat**（月額＋年額割引＋無料トライアル）→ **Paywall**。FR-15 の詳細ドリルダウン／バックアップ等を課金に。App Store Connect / Play の課金アイテム登録。**特商法表記**ページ | 初めて売上が立つ課金 MVP。薄く始めて反応を見る |
| **v1.3** | 入力の手間を殺す（モート①） | **CSV 取込**（SBI/楽天の配当・取引履歴 → 自動反映）＝Premium。カビュウ型の強みを取りに行く | 「手入力が面倒」を潰す＝乗り換え理由・継続率↑ |
| **v1.4** | 不正確を殺す（モート②） | **J-Quants 自動取得**（株価・配当。公式 JPX データで規約クリーン）。無料枠＝約12週遅延の制約は設計で吸収（現在値は手動上書き可、配当・銘柄名の自動補完に活用） | 最頻出不満「データ不正確」を潰す＝課金の最大理由 |
| **v2〜** | 磨き・拡張 | 米国株データ／増配率スコア／NISA 枠最適化／ホーム画面ウィジェット／価格・パッケージ調整／ASO 反復。**広告はここまで来て MAU が十分なら最小1バナーを再検討** | LTV と転換率の最適化 |

**この順の肝**：本命はモート（CSV/J-Quants）だが実装が重い。先に軽い FR-15 で v1.2 から薄く課金を開始して市場反応を取り、それを見ながら v1.3/1.4 で厚くする。いきなり重いモートに突っ込んで課金ゼロで消耗するのを避ける。

## 早めに潰す「要決定」

1. **特商法表記＝本名/連絡先の開示問題（v1.2 の前に必須）**：日本で有料サブスクを出すと特定商取引法の表記（販売者名・連絡先等）を求められる。ストアが決済代行のため緩和はされるが、**「App Store のデベロッパ名が本名で公開されている問題」と直結**する。マイクロ法人化（フリーランス 2 年目予定）や屋号 datz との整合で、課金前に「誰名義で売るか」を決める。→ [project_mydividend_app のメモ参照]
2. **FR-15 を"無料の撒き餌"にするか"課金の壁の中"に置くか**：無料に置くと ASO・差別化の看板になるが課金理由が一つ減る。**折衷＝基本（連続増配年数の表示）は無料・詳細ドリルダウン（推移グラフ/銘柄別増配履歴）は課金**が有力。v1.1 実装時に確定する。

## 追う指標（B としての健全性）

| 指標 | 意味 |
|------|------|
| ストア表示 → インストール率(CVR) | ASO・アイコン・スクショ |
| D1/D7 継続率 | 定着（宣伝より本質。悪いと穴の空いたバケツ） |
| 無料→課金 転換率 | マネタイズの核（想定 1〜2%） |
| 課金の解約率／年額比率 | LTV |
| レビュー数・平均★ | 信頼と検索順位に直結 |

## 割り切り（前提の明示）

- 課金転換は市場的に低い（1〜2%想定）。**大ヒット前提にしない**。まず定着（D7）→ 次に拡散、の順を守る。
- モートは重いので v1.2 で薄く課金開始 → 反応次第で v1.3/1.4 に投資、と段階的に。反応が絶望的なら A（ブランド資産）へ戦略転換する分岐も残す。
- Dev Build 移行後もネイティブ追加時は version を上げてストア再提出が要る（JS のみは OTA 継続）。
